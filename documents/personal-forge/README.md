# Personal Forge (`personal-forge`)

The **`personal-forge`** directory serves as a self-directed sandbox housing both `challenges` and `projects`. Unlike standard course syllabi, workshops, or platform-based coding platforms, all tasks in this directory are either driven by personal interest to solve real-world problems or designed through custom, AI-generated curricula (e.g., via ChatGPT).

---

## 1. Learning Methodology & AI Mentorship

The tasks within `personal-forge` follow an iterative learning workflow:

* **AI-Guided Curricula:** Generative AI models act as dynamic mentors, assigning targeted coding challenges followed by comprehensive projects to reinforce theoretical concepts.
* **Code Review & Assessment:** Each solution undergoes review to identify flaws, optimize performance, and highlight area-specific growth opportunities.
* **Self-Driven Exploration:** Focuses on practical problem-solving beyond rigid academic or standard course boundaries.

---

## 2. Directory & Subfolder Architecture

To maintain clarity and consistency across language modules, all task directories inside `personal-forge` follow a strict, standardized naming convention:

### Naming Format

$$\text{\textbf{(order)\_(purpose)\_(language)}}$$

* **`order`**: A numerical prefix tracking completion sequence chronologically. Lower numbers reflect foundational logic and earlier coding styles, while higher numbers demonstrate evolving proficiency, advanced patterns, and cleaner code standards.
* **`purpose`**: A concise descriptor of the module's core logic or problem statement.
* **`language`**: The file extension or language tag representing the implementation language.

---

### Example Breakdown

```text
15_armstrong_number_cpp
```

* **`15`**: Represents the **15th** completed task, showing progress over previous implementations.
* **`armstrong_number`**: Indicates the core program logic (calculating/validating Armstrong numbers).
* **`cpp`**: Specifies the implementation language (**C++**).

---

## 3. Task Documentation

Subfolders may include an internal `README.md` file providing:
* **Concept Explanation:** Background context on mathematical formulas, algorithms, or design patterns used.
* **Task Objectives:** Requirements provided during the problem definition stage.
* **Refactoring Notes:** Insights gained during mentor/AI review sessions.
