#  `challenges`

The **`challenges`** directory is a dedicated workspace focused on solving focused, isolated algorithmic problems—one task at a time. It emphasizes building core programming foundations, algorithmic intuition, and code optimization across multiple programming languages.

---

## 1. Scope & Objective

Unlike full-scale applications, programs within the `challenges` folder address specific, small-scale algorithmic problems (e.g., finding the `GCD`, calculating the `LCM`, or implementing sorting algorithms). 

* **Directory Contents:** Each task subfolder contains the implementation source code and, where appropriate, an accompanying task-specific `README.md` detailing the problem statement or logic.
* **Volume vs. Complexity:** Because tasks have simple, targezted objectives, new code solutions are committed routinely. Consequently, this folder holds a larger volume of files than the `projects` directory, prioritizing high-frequency skill building over complex system architecture.

---

## 2. Tested Skill Sets

Every challenge solution is crafted to evaluate and strengthen three key capabilities:

1. **Clean Code:** Writing readable, maintainable, and self-documenting code.
2. **Algorithmic Intuition:** Selecting appropriate data structures and logic flow to solve problems effectively.
3. **Space/Time Complexity:** Optimizing code execution efficiency and resource management.

---

## 3. Iterative Learning & Solution Refactoring

Occasionally multiple entries or subfolders share the same challenge name. This design choice supports continuous improvement:

* **Algorithmic Iteration:** Problems are periodically revisited to implement alternative algorithmic approaches (e.g., transitioning from a naive solution to dynamic programming or a mathematical shortcut).
* **Code Refactoring:** Solutions are updated over time to improve clarity, adapt idiomatic language features, or further optimize space and time constraints.
